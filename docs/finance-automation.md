# 재무 자동화 — 믿을 범위 · 자동 처리 · 돈의 흐름 잇기

2026-10-24 재무 자동화 1·2단계. 사람이 하던 확인을 프로그램에 넘기되, **넘긴 것은 언제나 보이고 되돌릴 수 있게** 한다.

## 1단계 — 자동분류를 어디까지 믿을지

| 장치 | 하는 일 | 코드 |
|---|---|---|
| 근거 꼬리표 | 엔진이 분류마다 어느 근거(같은 거래처·같은 계좌 · 이름 뼈대 · 카드 메모 · 업종 …)에서 나왔는지 남긴다. 적재 때 거래에 `engineCell` · `engineSig` 로 남는다 | `classify.ts` (`EvidenceBasis`) |
| 믿을 범위 | 확정 장부를 달마다 「그 달 이전 것만 보고」 다시 맞혀 근거 칸마다 실측 정확도를 잰다. 켜면 기준(기본 98% · 20건) 이상인 칸은 확정, 아래인 칸의 확정은 제안. **기본 꺼짐** | `trust.ts`, `server/trust.ts` |
| 계좌·카드별 범위 | 「제안만」 계좌·카드는 엔진이 확정하지 않는다 (규칙이 확정하라고 해도) | `trust.ts` |
| 자동으로 처리된 거래 | 엔진이 확정한 채 아무도 안 고친 거래를 근거 칸별로 묶어 보이고, 한 건·한 묶음씩 대기함으로 돌려보낸다 | `app/neander/finance/auto` |
| 확정 → 규칙 제안 | 같은 이름 뼈대 · 같은 계좌의 최근 확정 3건이 같고 엔진이 아직 스스로 확정 못 하면 규칙 초안 + 닿는 범위를 보인다. 저장은 사람이 누른다 | `rule-suggest.ts`, `RuleSuggestCard` |
| 묶음으로 묻기 | 대기함을 (이름 뼈대 × 계좌 × 방향 × 금액대)로 묶어 큰 묶음부터. 이력이 갈리는 묶음은 누르기 전에 묻는다 | `review-groups.ts`, `ReviewGroups` |
| 변경 이력 | 거래 쓰기마다 바뀐 칸만 한 줄 (`neander_fin_tx_log`). 남긴 사람은 서버가 찍고, 무엇으로(계속 배우기 · 묶음 확정 …)는 화면이 알려 준다. 거래 편집 창 아래 「기록」 | `tx-log.ts`, `server/tx-log.ts` |

## 2단계 — 이미 있는 데이터 잇기

| 장치 | 하는 일 | 코드 |
|---|---|---|
| 받을 돈 짝짓기 | 통장 입금을 프로젝트 입금 회차에 짝짓는다 — 부가세 포함 금액 · 수수료 3천 원 · 부분 입금 · 합산 입금 · 배운 입금자 이름. 「받음 처리」 를 누르면 회차가 받음(`received` · 입금일), 입금에 `receiptOf` · 프로젝트 코드 | `receivables.ts`, 자동 처리 화면, mutate `project.markReceived` · `project.unmatchReceipt` |
| 빠진 정기 지출 | 최근 8개월 3달 이상 같은 날(±6일) · 비슷한 금액(±15%). 그 계좌 내역이 예정일 뒤까지 올라왔는데 없으면 「빠짐」 | `recurring.ts`, 자동 처리 화면 |
| 월요일 브리핑 · 알림 | 7일 넘은 받을 돈 · (런웨이가 내다본) 통장 바닥만 알림. 브리핑은 한 장 | `briefing.ts` |

현금 예측(달마다 들어오고 나갈 돈 · 언제 모자라나)은 **런웨이 한 곳**이 맡는다 (리포트 › 런웨이, `runway.ts`). 13주 자금표를 따로 두었다가 2026-10-24 런웨이로 합쳤다 — 두 군데서 따로 세면 숫자가 어긋난다. 브리핑 · 알림은 런웨이의 결과(`runwayDanger` — 시작일 · 시작 잔액 · 처음 0 아래로 내려가는 날 · 가장 낮은 날)를 옮겨 적기만 한다.
| 월 마감 점검 | 「카드와 통장에 같은 결제」(warn) · 「이 달에 빠진 정기 지출」(info) | `close.ts` |
| 결제 알림 메일 → 카드 메모 | 회사 메일함(카페24 · 팀 공용)의 KCP · 토스페이먼츠 · 이지페이 · 헥토 · 쿠팡 · 해외 영수증을 정규식으로 읽어, 맞는 카드 거래가 하나뿐일 때 `[메일] 상점 / 품목` 메모를 붙인다. 단톡방 메모가 있으면 덮지 않는다 | `pay-mail.ts`, `server/pay-mail.ts` |
| 매일 밤 점검 | 06:00 KST — 믿을 범위 다시 재기 · 결제 메일 메모 · 알림 상태 · (월요일) 브리핑 | `app/api/neander/finance/cron`, `vercel.json` |

## 저장소

- `neander_fin_settings/trust` — 믿을 범위 설정 + 마지막 실측
- `neander_fin_settings/alerts` · `neander_fin_settings/briefing` — 매일 밤 점검의 알림 · 월요일 브리핑
- `neander_fin_tx_log` — 거래 변경 이력
- 거래 필드: `engineCell`(근거 칸) · `receiptOf`(짝지은 회차) · `cardChatId = mail:…`(메일에서 붙은 메모)

## 배포에 필요한 것

- Vercel 환경변수 `CRON_SECRET` — 매일 밤 점검이 이것으로 들어온다 (매출 동기화와 같은 값)

## 검증

```
npm run finance:verify-trust   # 관문 · 규칙 제안 · 묶음 · 변경 이력 + 실제 장부 칸별 실측 (읽기 전용)
npm run finance:verify-cash    # 받을 돈 · 정기 지출 · 결제 메일 + 실제 장부 (읽기 전용)
```
