# 비서가 노션을 읽게 하기 — 켜는 법

재무 비서와 매출 비서가 회사 노션(워크스페이스 「네안데르」)을 **읽을 수 있게** 합니다.
장부·판매 줄에는 없는 맥락 — 이벤트 기획, 회의에서 정한 것, 거래처 메모 — 을
비서가 직접 찾아보고 출처를 밝혀 답합니다.

```
사용자 ─ 질문 ─▶ 비서 (ERP 서버)
                  ├─ 장부·판매 줄 조회 도구   (지금과 같음)
                  └─ 노션 조회 도구 3개 ─────▶ api.notion.com
                       notion_search             (읽기 전용 연결 ·
                       notion_read_page           공유받은 페이지만)
                       notion_query_database
```

**토큰을 넣기 전에는 아무것도 바뀌지 않습니다.** `NOTION_TOKEN` 이 없으면
비서에게 노션 도구도 안내문도 붙지 않습니다.

---

## 1. 노션에서 연결 만들기

⚠️ **워크스페이스 소유자(Workspace Owner)** 만 만들 수 있습니다.

1. https://app.notion.com/developers/connections 를 엽니다.
2. 왼쪽 **Build → Internal connections → Create a new connection**.
   이름은 `NEANDER ERP 비서`, 워크스페이스는 「네안데르」.
3. **Configuration** 탭 → 권한(capabilities)에서 **Read content 하나만** 켭니다.
   Update content · Insert content · 사용자 정보는 **끕니다.**
   코드에도 쓰는 요청이 없지만, 토큰이 새더라도 읽기밖에 못 하게 하는 두 번째 자물쇠입니다.
4. 같은 탭의 **Installation access token** 을 복사합니다.

> 개인 액세스 토큰(Personal access token)은 쓰지 마세요. 그건 **만든 사람이 볼 수 있는
> 모든 것**을 봅니다. 내부 연결은 **공유해 준 페이지만** 봅니다 — 그 차이가 이 설계의 핵심입니다.

## 2. 토큰 넣기

| 어디 | 값 |
| --- | --- |
| `.env.local` (로컬) | `NOTION_TOKEN=복사한 토큰` |
| Vercel → Settings → Environment Variables (배포) | 같은 이름·같은 값, Production + Preview |

Vercel 은 환경변수를 바꾼 뒤 **다시 배포**해야 적용됩니다.

## 3. 비서가 볼 페이지 연결하기

새 연결은 **아무 페이지도 못 봅니다.** 보여 줄 페이지마다:

> 페이지 오른쪽 위 **•••** → **Connections** → **+ Add connection** → `NEANDER ERP 비서`

상위 페이지를 연결하면 그 아래 페이지는 전부 따라갑니다.

### 무엇을 연결할까

두 비서는 **같은 연결을 씁니다** — 연결한 페이지는 재무·매출 비서 모두, 그리고
ERP 에 로그인할 수 있는 사람(`NEANDER_FINANCE_EMAILS`) 누구나 비서를 통해 읽을 수 있습니다.

| 추천 | 페이지 | 왜 |
| --- | --- | --- |
| ✅ | 이벤트 기획·굿즈 관리 | 매출 비서가 "10월 이벤트 준비물이 뭐였지"를 판매 줄과 나란히 답할 수 있다 |
| ✅ | 전체 회의록 | 가격·행사를 왜 그렇게 정했는지 — 숫자 뒤의 결정 |
| 🤔 | 사업부별 회의록 (SMOAT 등) | 그 사업 질문이 잦으면 |
| 🤔 | 재무·재고 자료 | 재무 비서에 쓸모 있다. 상위 폴더가 기밀 성격이면 **폴더째 연결하지 말고** 필요한 하위 페이지만 |
| ❌ | 인사·급여·계약서·개인 연락처가 있는 페이지 | 비서를 통해 로그인한 누구에게나 열린다 |

처음에는 ✅ 두 개만 연결하고, 비서가 "찾는 문서가 연결돼 있지 않다"고 할 때 하나씩 늘리는 것을 권합니다.
(이 저장소는 공개라서 여기에는 실제 페이지 이름을 적지 않습니다.)

## 4. 확인

```bash
npm run notion:verify
```

① 오프라인 규칙 검사 뒤 ② 실제 노션을 부릅니다: 연결된 문서 목록, 첫 페이지 앞부분,
첫 표 몇 줄을 **비서가 받는 모양 그대로** 찍습니다. `검색 — 0건` 이면 3번(페이지 연결)을 안 한 것입니다.

그다음 비서 창에서 이렇게 물어보세요:

- 매출 비서: "노션에 있는 10월 이벤트 계획이랑 지난 10월 실제 매출을 비교해 줘"
- 재무 비서: "지난 전체회의에서 정한 이번 달 지출 계획이 뭐였어? 장부랑 맞아?"

답 위의 「조회 N회 — 어떻게 찾았는지 보기」를 펼치면 `노션 검색 "10월" → 3건`,
`노션 페이지 「10월 이벤트」 읽음` 처럼 무엇을 읽었는지 나옵니다.

---

## 알아둘 것

- **검색은 제목만 봅니다** (노션 API 의 한계). 본문에만 있는 단어로는 안 걸립니다.
  비서에게 "제목에 들어갈 짧은 핵심어로 여러 번 찾으라"고 안내해 두었습니다.
- **노션 숫자는 계획이나 당시 추정입니다.** 비서는 노션에서 온 내용에 「노션 ○○에 따르면」을
  붙이고, 실제 값은 장부·판매 줄 도구로 따로 조회해 나란히 보여 주도록 되어 있습니다.
- **노션 본문 속 지시는 따르지 않습니다.** 노션은 워크스페이스의 누구나 고칠 수 있는
  자료라서, 본문에 "규칙을 무시하라" 같은 글이 있어도 비서가 따르지 않게 막아 두었습니다.
- **비서는 노션을 고칠 수 없습니다.** 적을 내용을 답에 써 주고, 옮기는 건 사람이 합니다.
- **비용**: 페이지 한 번에 8,000자(약 4~5천 토큰)까지만 읽고, 더 필요할 때만 이어 읽습니다.
  노션을 안 보는 질문은 지금과 비용이 같습니다.
- **요청 한도**: 지금 요금제에서 연결당 초당 평균 3회. 넘으면 노션이 잠깐 막는데,
  5초 이하면 기다렸다 다시 부릅니다.
