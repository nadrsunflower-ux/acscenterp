# 오래된 회의 자료를 노션에 보관하기

회의 날짜가 **90일**을 넘긴 회의의 **첨부 파일과 녹음 음성**을 회사 노션으로 옮기고,
ERP에는 이름·크기·올린 사람과 링크만 남깁니다.

```
ERP 회의록                                  노션 「임원진 회의록」 (기존 페이지)
├ 회의록 본문      ← 그대로 ERP            ├ 📍 4월 27일        ← 사람이 쓰던 기존 회의록
├ 액션플랜        ← 그대로 ERP            ├ 📍 5월 1일
├ 받아쓴 글·AI 초안 ← 그대로 ERP           ├ 📍 5월 8일
└ 첨부·녹음 음성   ── 옮김 ──────────────▶ └ 📍 6월 21일 [스모트] 업무 분담   ← 이어서 쌓임
   (ERP에는 링크만)                              ├ ERP 회의록 링크
                                                 ├ 회의 내용 · 액션플랜 (사본)
                                                 ├ 📄 6월 19일 … (자료)   ← 자료는 회의 페이지 안에
                                                 ├ 첨부 파일 (올린 사람별)
                                                 └ 녹음 음성 (10분 조각)
```

**이미 쓰던 페이지에 이어서 쌓습니다.** 「임원진 회의록」에는 회의마다 📍 페이지가
하나씩 있습니다(「5월 8일」). 보관한 회의도 같은 모양으로 그 아래에 이어 붙습니다.
ERP에서 어떤 회의의 **자료**로 묶어 둔 문서는 노션에서도 그 회의 페이지 **안에**
들어갑니다(📄). 상위 회의에 옮길 자료가 없어도, 자료를 담을 회의 페이지는 만듭니다.

**왜 옮기나**: Firebase Storage가 없어 첨부와 음성이 Firestore에 쌓입니다. 무료 1GB를
장부·매출·메일과 나눠 쓰기 때문에 오래 두면 ERP 전체가 막힙니다. 회사 노션은 유료라
파일 하나에 5GiB까지 넉넉합니다.

**토큰을 넣기 전에는 아무것도 바뀌지 않습니다.** 보관 창은 열리지만 「설정되지 않았습니다」로
표시되고, 아무 파일도 움직이지 않습니다.

## 설정 (2026-09-22 완료)

로컬 `.env.local`에 다음 두 줄이 들어 있습니다. **배포할 때 Vercel 환경변수에도**
같은 값을 넣고 재배포해야 팀원들이 씁니다.

```bash
NOTION_ARCHIVE_TOKEN=ntn_...                     # 노션 연결 「NEANDER ERP 보관」 토큰
NOTION_ARCHIVE_PAGE=https://app.notion.com/...   # 「임원진 회의록」 페이지 주소 (id만 넣어도 됩니다)
```

연결을 새로 만들어야 한다면 (워크스페이스 소유자만 가능):

1. https://app.notion.com/developers/connections → **Internal connections → Create a new connection**
   (이름 `NEANDER ERP 보관`, 워크스페이스 「네안데르」)
2. **Configuration** 탭 → 권한: **Read content** ✅ · **Insert content** ✅.
   Update content는 없어도 보관은 됩니다(페이지 이름 바꾸기·휴지통 보내기에만 필요).
3. 같은 탭의 토큰(`ntn_…`)을 복사합니다.
4. 보관함 페이지에서 `••• → 연결 → NEANDER ERP 보관`을 붙입니다. 그 페이지 아래는
   권한을 물려받습니다. **다른 페이지에는 붙이지 마세요** — 붙인 페이지가 이 연결이
   할 수 있는 전부입니다.

비서가 쓰는 읽기 전용 연결(`NOTION_TOKEN`)과는 **다른 연결**입니다. 그래야 비서는
계속 아무것도 못 쓰고, 이 연결이 새더라도 건드릴 수 있는 건 보관함뿐입니다.

## 쓰는 법

ERP 회의록 화면 오른쪽 위 **상자 아이콘(오래된 회의 자료 보관)** 을 누릅니다.

- 보관함 이름(「임원진 회의록」)이 보이면 연결이 된 것입니다.
- 목록에 90일 넘은 회의와 옮길 용량이 뜹니다. **「N건 노션으로 옮기기」** 를 누르면 한 건씩 옮깁니다.
- 옮긴 뒤 ERP 첨부 칸은 「… · 노션에 보관됨」으로 바뀌고, 누르면 노션에서 열립니다.

코드만 확인하려면 (노션 없이 도는 부분):

```bash
npm run meetings:verify-archive
```

## 규칙 몇 가지

- **되돌릴 수 없는 삭제는 마지막에.** 파일을 노션에 올리고 → 페이지에 붙이고 → 블록 id를
  ERP에 적은 **뒤에야** Firestore 조각을 지웁니다. 중간에 실패하면 아무것도 지우지 않고,
  다시 돌리면 남은 것부터 이어서 합니다(이미 적은 소제목·사람 이름은 다시 쓰지 않습니다).
- **한 파일이 막혀도 나머지는 옮깁니다.** 못 옮긴 파일은 ERP에 그대로 두고, 보관 창에
  「N개는 옮기지 못해 ERP에 그대로 두었습니다」로 이유와 함께 보여 줍니다.
- **노션이 안 받는 확장자는 압축해서 올립니다.** 노션 파일 업로드는 받는 확장자가
  정해져 있어 `.hwp`·`.alz` 같은 것은 거절합니다. 그런 파일은 gzip으로 감싸
  `기획안.hwp.gz`로 올리고, 설명에는 원래 이름을 적습니다. 받아서 풀면 원래 파일입니다.
  (`.zip`·`.pdf`·`.docx`·`.xlsx`·`.ogg`·`.m4a` 등은 그대로 올라갑니다)
- **크롬 녹음(webm)은 노션이 동영상으로 봅니다.** 그래서 음성 블록이 아니라 파일 블록으로
  붙입니다. 휴대폰 녹음을 올린 것(ogg·m4a)은 노션에서 바로 들을 수 있습니다.
- **한 번에 회의 하나씩.** 30MB 파일을 올리는 동안 서버 시간(300초)을 넘기지 않게 화면이
  회의를 하나씩 부릅니다. 20MiB가 넘는 파일은 10MiB씩 조각내 올립니다(노션 규칙).
- **노션 파일 주소는 1시간이면 만료됩니다.** 그래서 ERP는 주소를 저장하지 않고, 누를 때마다
  노션에서 새 주소를 받아 새 탭으로 엽니다.
- **회의록 본문·액션플랜·받아쓴 글·AI 초안은 ERP에 그대로 남습니다.** 글이라 작고, 비서와
  검색이 읽어야 합니다. 노션 페이지에는 읽기 좋으라고 본문과 액션플랜 사본이 함께 들어갑니다.
- 기준일(90일)은 `lib/neander/meetings/server/archive.ts`의 `ARCHIVE_AFTER_DAYS`입니다.
- 회의 페이지 이름은 기존 페이지와 같은 **`6월 21일 제목`** 모양입니다. 만든 페이지 주소는
  회의 문서의 `notionPageUrl`에 적어 두어, 다시 돌려도 페이지를 두 번 만들지 않습니다.

## 실제로 확인한 것 (2026-09-22)

점검용 회의 2건(상위 회의 + 자료)으로 노션에 실제로 옮겨 보고 지웠습니다.

- 보관 창 → 「2건 노션으로 옮기기」 → 「임원진 회의록」 맨 아래에 📍 회의 페이지, 그 안에 📄 자료 페이지.
- `.pdf`는 그대로, `.hwp`는 `.hwp.gz`로, 녹음 `.ogg`는 음성 블록으로 들어갔습니다.
- 노션에서 다시 받아 **바이트가 완전히 같은지** 확인했습니다(21MB 파일로 조각내 올리는 길도 확인).
- 옮긴 뒤 ERP 조각(Firestore)은 0개가 되고, 첨부 줄은 「노션에 보관됨」이 되며, 누르면
  노션 파일이 새 탭에서 열립니다.
