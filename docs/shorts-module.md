# AI STUDIO 워크스페이스 (/neander/shorts)

AI 로 만드는 영상을 한 흐름으로 다룬다. 영상은 세 종류다.

- **쿠팡 제휴 영상** — 소재 발굴 → 중국어 소스 → 쿠팡 동일 상품 → 성공 공식 · 대본 → 편집 · 출력 → 계정 게시 → 성과.
- **고객사(브랜드) 영상** — 고객사 계약 · 브리프 · 제품 → 월별 영상 → 편집 · 출력 → 고객 검토(링크) → 승인한 파일만 게시 → 월간 보고.
- **일반 영상 (제휴 없음)** — 제휴 링크 · 협찬 · 대가가 없는 영상(예: 다이소 목록 · 살림 정보). 고지 문구 · 영상 안 고지 띠 · 「쿠팡 확인」 탭이 없고, 확인 항목은 「제휴 링크 · 협찬 · 대가 없음」(프로그램이 제목 · 문구 · 대본에서 쿠팡 링크와 「쿠팡 파트너스 · 유료 광고 · 협찬」 을 찾고 사람이 확인 — 찾으면 사람 확인으로 못 넘김) · 표현 확인 · 소스 기록(선택)뿐이다. 쿠팡 ↔ 일반은 영상 화면 위에서 바꾸고, 고객사 영상과는 서로 바꿀 수 없다. 고객사 소유 계정에는 올리지 않는다. 쿠팡 파트너스 승인 전에도 게시를 시험할 수 있다.

이름: 화면에는 **AI STUDIO**(워크스페이스) · **영상**(「내 영상」 「새 영상」)으로 보인다. 처음 이름이 「쇼핑쇼츠」 라서 주소(`/neander/shorts/*`) · 컬렉션(`neander_shorts_*`) · 코드 이름(`ProjectDoc` · `projectId` 등)은 그대로 둔다. 플랫폼 형식인 「쇼츠」(YouTube Shorts)는 그대로 쓴다.

프로토타입(`~/Developer/shoppingshorts/studio`)의 모델 · 게시 어댑터 · 프롬프트 원칙을 옮겼다. Cloudflare(Sites 인증 · D1 · R2)는 ERP 의 Google 로그인 · Firestore · 서버 API 로 바꿨다.

## 권한 · 데이터 분리

- 입장: NEANDER 팀원(`requireMember`). `NEANDER_SHORTS_EMAILS` 가 있으면 그 목록만.
- 문서마다 `owner` · `visibility`. 비공개는 소유자만, 팀 공개는 모듈 사용자 누구나 읽고 고친다. 지우기 · 공개 범위 바꾸기는 소유자만.
- 게시 계정은 연결한 사람의 것. 소유자가 `sharedWith` 에 팀원을 넣어야 그 사람이 게시할 수 있다. 토큰은 AES-256-GCM(AAD = 계정 문서 id)으로 서버에만.
- 출처 위조 막기: 숫자의 `src: "api"` 는 서버가 공식 API 로 받아 적을 때만 생긴다. 확인한 사람(동일 상품 · 정책 확인 · 제휴 링크)은 서버가 요청자로 찍는다.

## 사람별 채널 세트 · 몰아보기

- 사람마다 **채널 세트**를 따로 둔다: 내가 연결한 YouTube · Instagram 계정 + 내 쿠팡 파트너스 키(Access · Secret, AF 코드) + 채널 아이디(subId) 목록 + (선택) 내 YouTube 검색 키. `neander_shorts_profiles/{ERP 이메일}` · 키는 암호문(AAD = `profile:` + 이메일) · 화면에는 끝 4자리와 상태만.
- 쿠팡 키는 공유하지 않는다 (파트너스 FAQ: API 키 1개 · 공유 불가). 계정은 공유할 수 있지만, 그 계정용 딥링크는 **계정 주인의 키 · 계정의 채널 아이디**로 서버가 만든다.
- 어느 키를 쓰나: 검색 = 내 키 → 없으면 회사 공용 키(환경변수) · 딥링크 = 게시 계정 주인의 키(회사 키로 대신 안 함) · 리포트 = 각자 자기 키로 자기 링크(`affiliate.coupangOwner`)의 실적만 · 쿠팡 429 면 24시간 그 키를 부르지 않는다.
- 게시 전 점검이 「제휴 링크 주인 = 게시 계정 주인」 을 본다 — 다르면 막는다 (그 사람의 파트너스에 등록되지 않은 채널에서 활동하는 셈).
- 화면 위쪽 「보기」: 내 것(기본) · 볼 수 있는 전체 · 사람별. 「사용자별 현황」(`/neander/shorts/team`)은 사람마다 채널 세트 · 쿠팡 키 상태 · 영상 · 게시 · 성과를 한 줄로.
- AI STUDIO 관리자(`NEANDER_SHORTS_ADMIN_EMAILS`, 없으면 `NEXT_PUBLIC_NEANDER_ADMIN_EMAILS`)는 모든 사람의 것을 **읽기 전용**으로 본다 — 남의 비공개 영상은 탭이 잠기고, 고치기 · 생성 · 게시는 서버가 막는다. 관리자가 아니면 자기 줄과 팀 공개만.

## 고객사(브랜드 대행) · 고객 검토

- `neander_shorts_clients` — 계약(월 금액 · 부가세 · 월 편수 · 한 편당 수정 횟수 · 시작/끝 월 · 재무 코드) · 브리프(요약 · 대상 · 말투 · 핵심 메시지 · 반드시 넣을 것 · **금지 표현** · 참고) · 제품(확인된 사실 · 실사진) · 담당자. **조회수 약속 칸은 없다.**
- 권한: 담당자(`members`)만 읽고 고친다 · 만든 사람은 늘 담당자 · 지우기는 만든 사람(영상 · 고객사 계정이 남으면 거절). 관리자는 읽기만. 담당자 목록은 그 고객사의 영상(`members`) · 고객사 계정(`clientMembers`)에 사본으로 붙고, 바뀌면 함께 고친다.
- 영상 추가: 그 달 계약분(`month`) · 제품의 사실이 대본 재료 · 정찰 형식 카드를 고르면 훅 · 구성 · 편집이 참고 자료로. 올릴 곳 = 고객사 계정(자기 광고 — 고지 없음) 또는 우리 채널(「광고 · {고객사} 유료 광고」 첫 줄 + 영상 안 고지 띠).
- 고객 검토: 「검토 보내기」 → `/neander/review/<토큰>` (30일 · 로그인 없음 · 그 영상 한 편만). 토큰은 저장하지 않는다(문서 id = sha256). 회차마다 한 번만 답하고, 새 회차가 나가면 앞 링크는 거둬들인다. 수정 요청은 계약의 수정 횟수로 세고, 넘은 요청도 기록하되 「계약 범위 밖」(`extra`)으로 표시. 카톡 · 메일로 받은 답은 담당자가 대신 기록(누가 기록했는지 남음).
- 게시: 브랜드 영상의 점검 항목은 (우리 채널이면) 고지 2개 + **고객사 승인**(승인된 그 파일만 · 사람 확인으로 넘길 수 없음) + 금지 · 의심 표현 + 소스 출처(선택). 쿠팡 항목은 없다. 다른 고객사의 계정 · 고객사 계정에 쿠팡 영상은 막는다. 예약 · 게시된 뒤에는 「승인 취소」 불가.
- 월간 보고 `/neander/shorts/clients/<id>/report?month=YYYY-MM` — 브라우저 인쇄 → PDF. 성과는 기록된 값만(출처 표시) · 「조회수는 계약상 약속이 아님」 · 다음 달 제안은 정찰 주간 보고에서.

## AI 레이더 (소재 발굴 맨 위)

매일 아침 cron(⑤)과 화면의 「지금 돌리기」 가 키워드로 YouTube 쇼츠를 훑어 「반응 큰 상품 후보」 를 모은다. 회사 공용 (`neander_shorts_radar`, 문서 id = `yt_<영상 id>`). 코드는 `lib/neander/shorts/radar.ts`(순수 계산) · `server/radar-run.ts`(실행) · `server/naver.ts` · `app/api/neander/shorts/radar` · `components/neander/shorts/radar/RadarPanel.tsx`.

1. 검색어(기본 10개 — 살림 · 주방 · 수납 · 청소 · 다이소)마다 search.list 1회. 계수기는 소재 발굴과 같은 `ytsearch_<날짜>`(하루 90회).
2. 쇼츠 길이(3분 이하) · 최소 조회(기본 1만)로 거르고, 채널 평소 조회수(최근 쇼츠 중앙값 — 정찰과 같은 산식, 채널 25곳까지) 대비 배수 · 하루 조회 속도(두 번 본 영상은 실제 증가) · 댓글 표본(20편까지)의 정보 요청 비율.
3. 점수 0~100 = 배수 40 + 속도 40 + 정보 요청 20 (모르면 0).
4. AI(기본 Gemini Flash)가 **영상을 보지 않고** 제목 · 설명 · 태그 · 댓글 글로 상품을 추정한다(8편씩 · 셋씩 함께 · 한 번에 64편까지 · 응답이 잘리면 반씩 다시). 「N가지 · BEST」 같은 모음 영상은 상품을 고르지 않는다. 하루 비용 상한(기본 1,000원, 1달러 = 1,450원 어림)에 닿으면 내일로 — 2026-11-02 실측 8편 약 $0.01.
5. 네이버 데이터랩 검색어 트렌드(상품 묶음마다 1회 · 3일 안에 본 것은 다시 안 봄): 최근 2주 ÷ 그 전 6주 → 상승(1.3↑) · 유지 · 하락(0.75↓) · 「검색 적음」(데이터랩 기준 — 국내에 없다는 단정이 아님).
6. 「소재로 저장」 은 그 사람의 소재(비공개)로 옮긴다 — 상품은 `identification.likely`(AI 추정) · 숫자는 API · 메모에 근거. 「제외」 는 회사 공용으로, 누가 뺐는지 남는다. 45일 넘게 다시 안 보인 후보는 지운다(저장한 것은 남김).

화면: 필터(분류 · 상품 상태 · 국내 검색 · 평소 대비 배수 · 올린 지 · 찾은 검색어 · 낱말 · 정렬 — `radar.ts` 의 `filterRadarGroups`, 이 브라우저에 기억)와 **화면 안 플레이어**(카드를 누르면 새 탭 대신 창 안에서 YouTube 퍼가기 플레이어 `youtube-nocookie.com/embed` 로 틀고, 오른쪽에 근거 · 저장 · 제외, ← → 로 지금 필터 순서대로 앞뒤 후보).

사람 표시 (2026-11-02): 카드의 「메모」 · 쇼츠처럼 보기 오른쪽 칸에서 ① **직접 촬영 / 직접 촬영 아님**(크리에이터가 직접 찍은 실사인가 — 회사 공용 · 마지막에 고른 사람 · 드로어 단축키 1 · 2 · 0 · 필터 「촬영」 · 목록 머리 집계) ② **메모**(회사 공용 · 한 사람에 하나 · 칸을 벗어나면 저장) 를 남긴다. 둘 다 AI 에 넘긴다 — 아침 자동 분석에 함께 들어가고, 「메모 반영해 다시 분석」 은 그 영상 하나만 다시 본다(설명 · 태그 · 댓글 표본 다시 받기 · 약 2원 · 레이더 하루 상한 안 · 상품 검색어가 바뀌면 네이버 추세도 그 자리에서). 분석이 지금 표시를 다 반영했는지는 `radarNoteState`(AI 요약 줄의 「사람 표시 반영 / 반영 전」). **레이더 실행은 후보 문서를 `mergeFields` 로 쓴다 — `notes` · `filmed` 는 실행이 덮지 않는다.** 좋아요 · 댓글은 카드의 반응 3칸(저장 · 공유는 YouTube 가 공개하지 않아 「비공개」), 댓글 원문은 `GET radar?comments=<id>&order=relevance|time&page=` 로 열 때 읽는다(commentThreads 1단위 · 저장 안 함 · 레이더 후보만). 쇼츠처럼 보기는 마지막으로 본 후보를 이 브라우저에 기억해(`neander.shorts.radarFeedLast`) 「이어 보기 · N번째」 · 「처음부터」 를 고른다.
바이럴 형식 「터진 영상」 의 메모도 AI 가 영상을 볼 때 초점으로 참고한다(영상과 어긋나면 영상을 따르고 summary 에 「메모와 다름」). 분석에 쓴 메모는 `analysis.note` 에 남겨 `hitNoteState` 로 「메모 반영해 다시 분석」 을 띄운다.

설정(검색어 · 기간 · 최소 조회 · 검색 수 · AI 상한 · 자동 켜기)은 AI STUDIO 관리자만 바꾼다. 검증: `npm run shorts:verify-server` 14번 구간(YouTube · AI · 네이버 모의).

## 완성 파일 — 바로 올리기 · 게시 뒤 지우기 (2026-11-02)

사용자 결정: 완성 파일은 수백 MB 라 **서버에 보관하지 않는다** — 게시가 끝나면 지우고 YouTube · Instagram 링크로 본다.

- **다 만든 영상 바로 올리기**: 게시 탭 「완성 파일」 카드의 「다 만든 영상 올리기 (MP4)」. 다른 도구로 만든 MP4 · MOV 를 출력기 없이 완성 파일로 올린다(`direct`). 브라우저가 코덱 · 길이 · 해상도를 읽어 함께 보낸다(게시 점검의 H.264/AAC 확인). 다 오르면 서버가 영상의 `renderIds` 에 넣는다(`completeMedia`).
- **저장 위치**: 완성 파일은 Firebase Storage 버킷이 켜져 있으면 버킷(`server/bucket.ts` · `neander_shorts/media/{id}` · 하나 **500MB** · 버킷 전체 `NEANDER_SHORTS_BUCKET_QUOTA_MB` 기본 5GB), 아니면 예전처럼 Firestore 조각(하나 60MB). 버킷 존재는 서버가 확인해 기억한다(있으면 10분 · 없으면 2분) — **버킷을 켜면 코드 수정 없이 바뀐다.** 2026-11-02 기준 버킷 없음.
  - 버킷 올리기: 서버가 재개형 업로드 세션을 열고(origin 지정 → CORS) 브라우저가 세션 주소로 바로 PUT. 끊기면 `media` 「status」 로 받은 곳을 물어 이어 보낸다(5번). 보기 · 받기 · 고객 검토 링크는 1시간 서명 URL. `storage.rules` 의 `neander_shorts` 는 닫혀 있다(서버만).
- **게시**: YouTube 는 48MB 씩 나눠 보낸다(`yt_session` → `yt_chunk` 반복). 조각마다 먼저 세션에 「어디까지 받았나」 를 묻기 때문에 끊겨도 이어 가고, 마지막 응답을 놓쳐도 다음 물음에 영상 id 가 온다 — 끊김은 이제 `uncertain` 이 아니라 잠시 뒤 다시(8번 넘게 연결이 안 되면 그때 `uncertain`). Instagram 은 버킷 파일이면 서명 URL(6시간)을 `video_url` 로 넘겨 Meta 가 가져가고, 조각 파일이면 예전대로 rupload. Instagram API 는 릴스 한 편 **300MB** 까지라 넘으면 게시 점검이 막는다.
- **지우는 때** (`model.ts` `shouldPurgeRender` · `canExpireRender` → `media.ts` `purgeAfterPublish` · `tidyRender`):
  - 이 영상을 올릴 수 있는 채널(올린 사람 · 게시한 사람이 쓸 수 있는 계정의 플랫폼)에 **모두 게시됐으면 바로**.
  - 한쪽에만 올렸으면 **마지막 게시 하루 뒤**(다른 쪽에 마저 올릴 시간) — 매일 cron 이 본다.
  - 실패 · 결과 확인 필요 · 보내는 중 · 예약이 남으면 지우지 않는다.
  - 아무 데도 안 올린 완성 파일은 **7일 뒤**. 고객사가 검토 중이거나 승인한 파일은 남긴다(승인한 그 파일만 게시할 수 있으므로).
  - 영상 설정 「게시가 끝나도 완성 파일 남기기」(`publish.keepFiles`)를 켜면 둘 다 안 한다.
- 지울 때는 내용(조각 · 버킷 객체)만 지우고 문서는 남긴다 — `purged{at, reason, by}` · 이름 · 크기 · 길이. 게시 기록이 이 id 를 계속 가리키고, 화면은 「게시 뒤 지운 파일 · 링크」 로 보여 준다. 다시 게시하려 하면 같은 계정이면 「이미 게시됨」, 아니면 「다시 올려 주세요」.
- 한도 계산은 색인 없이 필드 하나씩 합한다: `size` 전체 − `purgedSize`(지운 조각 파일) − `bucketBytes`(버킷에 쥔 것) = Firestore 조각으로 쥔 양. 두 필드를 한 집계에 넣거나 조건을 붙이면 복합 색인이 필요하다(권한 없음).
- 검증: `shorts:test`(publish-files.test.ts — 나눠 보내기 · 끊김 · 세션 만료 · id 없음 · 조각 크기 · video_url · 지우는 때) · `shorts:verify-server` 7 · 8 · 8-1번(재개형 모의 YouTube · 한쪽만 올리면 남김 · 둘 다 올리면 지움 · 하루 뒤 · 7일 · 파일 남기기 · 바이트 구간 읽기 · 바로 올리기). **버킷 경로는 버킷이 없어 실제로 돌려 보지 못했다** — 켠 뒤 큰 파일 한 편으로 올리기 → YouTube 비공개 게시 → 지워지는지 확인할 것.

## 바이럴 형식 정찰 (/neander/shorts/scout)

쿠팡 제휴 영상과 고객사 영상이 같이 쓰는 「요즘 무엇이 먹히나」 정보. 회사 공용이다 (visibility 없음 · 지우기는 만든 사람 · AI STUDIO 관리자, 자동 수집 문서는 관리자만).

| 자리 | 내용 |
| --- | --- |
| `lib/neander/shorts/scout.ts` | 타입 · 평소 조회수 · 배수 · 형식 수명 · 나라별 처음 본 날 · 시차 · 주간 보고 집계 (순수 함수) |
| `lib/neander/shorts/server/scout-store.ts` | `neander_shorts_watch` · `_hits` · `_formats` · `_reports` · 설정(`neander_shorts_settings/scout`) |
| `lib/neander/shorts/server/scout-run.ts` | 훑기 · 영상 분석 · 자동 분석 · 주간 보고 · cron |
| `lib/neander/shorts/server/scout-ai.ts` | 영상 보기(OpenRouter `video_url` — Gemini 가 공개 YouTube 주소를 직접 본다) · 보고 요약 |
| `app/api/neander/shorts/scout` | GET 한 벌 · POST 동작 (`watch.*` · `hit.*` · `format.*` · `report.*` · `settings.save`) |
| `components/neander/shorts/scout/*` | 주간 보고 · 터진 영상 · 형식 카드 · 감시 채널 탭 |

- **터진 영상** = 3분 이하 · 올린 지 30일 안 · 1만 회 이상 · 그 채널 평소의 3배 이상 (설정에서 바꾼다). 평소 = 최근 쇼츠 중 올린 지 7일 넘은 것 최대 30편의 조회수 중앙값 (모자라면 어린 영상까지 · 그래도 5편 미만이면 모름).
- **훑기**는 채널 하나에 약 3단위(playlistItems · videos · channels) — search.list(하루 100회)는 「채널 찾기」 · 「국내 검색」 에서만.
- **형식 카드** = 소재가 아니라 「어떻게 만들었나」. AI 분석이 기존 카드와 같은 형식을 제안하고(목록에 없는 id 는 버림), 사람이 묶는다. 카드마다 나라별 처음 본 날 · 한국 상태 · 시차가 계산된다. 게시일을 모르는 직접 등록 영상은 찾은 날로 센다.
- **수명**: 씨앗(한 편) · 떠오름(최근 2주 두 채널 이상 · 주당 편수가 그 전 4주 이상) · 포화 조짐(6편 이상 · 최근 배수 중앙값이 그 전의 60% 밑) · 식음(6주 넘게 없음) · 유지.
- **한국 상태**: 국내 검색 표본에서 사람이 고른 것 + 국내(KR) 터진 영상. 표본에서 못 찾은 것은 「국내 표본에 없음」 이지 없다는 단정이 아니다. 카드 저장으로는 바뀌지 않는다 (검색 · 표시 동작으로만).
- **AI 분석**은 YouTube 영상만 (틱톡 · 더우인 · 샤오홍슈 · 인스타는 링크 + 사람이 본 숫자로 등록, 카드는 직접). 한 편 약 10원(19초 영상 실측 $0.0069). 해외 영상은 분석할 때 댓글 100개 표본의 한글 비율도 잰다.
- **매일 아침 07:00 cron-scout**(따로 · 5분): ① 감시 채널 자동 채우기(한국 = AI 레이더가 찾은 영상 중 채널 평소의 3배 이상 · 해외 = 미국 · 일본 · 대만 · 중국(간체, 홍콩 지역 검색) 나라마다 검색 1회 · 검색어는 날마다 돌림 · 평소 대비 3배 이상 영상이 있는 채널만 · 나라마다 하루 5곳 · 최대 20곳 · 주제 「자동 추가」 · 사람이 지운 채널은 다시 안 넣음) → 훑기 → 새 영상 자동 분석(하루 상한 기본 10편) → ② 자동 묶기(AI 분석이 기존 카드와 같다고 본 것은 바로, 나머지는 AI 가 하루 한 번 묶어 2편 이상이면 카드를 만듦 · owner company · 메모 「AI 자동 묶음」) → ③ 한국 확인(카드마다 주 1회 · 하루 2장 · AI 가 국내 표본의 제목 · 설명으로 판단, 영상은 안 봄 · 사람이 30일 안에 표시한 카드는 안 덮음) → 주간 보고 → ④ AI 요약. 설정은 정찰 화면 맨 위 「자동화」(관리자). `lib/neander/shorts/scout-auto.ts` · `server/scout-auto-run.ts` · `app/api/neander/shorts/cron-scout` · `scout-auto`. 2026-11-02 첫 실행: 채널 19곳 · 터진 영상 87편 · 카드 2장 · AI 148원 · 2분 22초.

## 시장 트렌드 (/neander/shorts/market · 기획)

감시 채널 · 내 채널 숫자, 네이버 데이터랩 검색어 추이, 레이더 상품 추이를 한 화면에 모으고, AI 가 매일 아침 특기할 것을 골라 브리핑한다. 사람은 마음에 드는 것을 「트렌드 노트」 에 보관해 정리하고 노트에서 바로 대본 작성기로 넘긴다. 2026-11-02.
