# 메일 — 카페24 회사 메일을 ERP 안에서

카페24 웹메일에 따로 로그인하지 않고 ERP `/neander/mail` 에서 받고 보냅니다.
팀원마다 메일 계정을 **여러 개** 로그인해 두고 왼쪽 판 맨 위에서 오갑니다 (예: 개인 메일 +
공용 문의 메일). 화면은 카페24 웹메일과 같은 차례이고, 세 칸(메일함 · 목록 · 읽기)이
한 판에 붙어 있습니다.

### 네이버 · Gmail (IMAP)

회사 메일(카페24)과 함께 네이버·Gmail 을 계정으로 붙인다 (`lib/neander/mail/server/imap.ts`, imapflow).
- 받기 IMAP 993 · 보내기 SMTP (네이버 587 STARTTLS · Gmail 465). 비밀번호 칸에는 **앱 비밀번호**
  (네이버: 2단계 인증 → 애플리케이션 비밀번호 + IMAP/SMTP 사용함 · Gmail: 2단계 인증 → 앱 비밀번호).
  회사 Google Workspace 계정은 2025년부터 비밀번호 로그인이 막혀 OAuth 가 따로 필요하다 (미구현).
- 서버의 받은메일함·보낸메일함·스팸을 가져온다 (특수 용도 표시로 폴더를 찾는다). 과거 보낸 메일도
  백업 zip 없이 「예전 메일 더 가져오기」로 읽는다. 받을 때 `BODY.PEEK` 라 서버 읽음이 바뀌지 않는다.
- ERP 의 읽음·중요·영구 삭제를 서버에 건다. 다른 곳에서 바꾼 읽음·중요는 CONDSTORE(HIGHESTMODSEQ)가
  있으면 바뀐 것만 받아 온다. 휴지통·내 메일함 옮기기는 ERP 안에서만이다.
- 두 서비스 모두 SMTP 로 보낸 메일을 서버 보낸메일함에 스스로 남긴다 — 사본을 따로 보내지 않고,
  들어온 서버 사본을 ERP 보낸 문서에 Message-ID (없으면 같은 제목 · 10분 안)로 이어 한 통으로 둔다.
- Gmail·네이버에 20초마다 로그인하면 막힐 수 있어 **1분에 한 번**만 붙는다 (새로고침 단추는 바로).
- 시험: 실제 계정이 없어 시험용 IMAP 서버(hoodiecrow)로 받기·건너뛰기·표시 양방향·원문·예전 메일·
  영구 삭제를 돌렸다. 실제 imap/smtp.gmail·naver 에는 틀린 로그인으로 접속·거절 구분만 확인했다.

### 여러 계정

- 계정 문서 키: 사람의 **첫 계정은 ERP 이메일 그대로**(예전 모양과 같다), 더 붙인 계정은
  `ERP이메일#무작위`. 문서의 `user` 필드가 주인이다 (예전 첫 계정은 처음 조회할 때 채운다).
- 요청마다 `acct`(계정 키)를 보내고 서버가 `resolveAccount` 로 **내 계정인지** 확인한다.
  남의 계정은 「팀 공유」 폴더만 읽기 전용으로 열린다 (`resolveBox`).
- 20초 확인 한 번이 **모든 계정**을 돈다 (45초 한도). ERP 사이드바 배지는 모든 계정의
  안 읽은 수 합, 계정 목록에는 계정마다 따로 붙는다. 새 메일 알림에 계정 주소가 붙는다.
- 메일쓰기 창의 「보내는 계정」으로 고른 계정의 SMTP 로 보낸다. 답장 원본은 내 다른
  계정의 메일이어도 된다. 임시저장·예약·보낸메일함·수신확인·주소록은 계정마다 따로다.
- 첨부 조각(blobs)은 계정이 아니라 **ERP 사용자** 것이다 — 어느 계정으로 보내든 쓸 수 있다.

### 팀 공용 계정

- 계정 문서에 `team: true` 면 **ERP 팀원 모두**의 계정 목록에 나온다 — 팀원은 앱 비밀번호 없이
  받고 보낸다 (`canUse` = 주인이거나 공용). 공용 Gmail nadr110619@gmail.com 이 이렇게 켜져 있다.
- 켜고 끄기 · 비밀번호 바꾸기 · 연결 끊기 · 다시 연결은 **연결한 사람(`user`)만** (`ownerOnly`).
  설정 창에서 주인은 「팀 공용 계정」 스위치를, 나머지는 「공용 계정 — 누가 연결」 안내만 본다.
- 읽음·중요·별칭·서명·주소록·임시저장·예약은 계정 것이라 **팀원이 함께 쓴다** (한 사람이 읽으면
  모두에게 읽음). 첨부 조각 · 임시저장 · 예약은 실제로 쓴 사람(`by`)의 조각으로 다룬다.
- 팀원 모두가 20초마다 확인하므로 IMAP 확인은 계정 문서의 `imapRunUntil`(55초 자리)을 트랜잭션으로
  잡은 한 곳만 서버에 붙는다. 같은 주소를 팀원이 따로 연결하려 하면 「이미 팀 공용」으로 막는다.

## 0. 한눈에

```
브라우저(ERP 열어 둔 탭)            ERP 서버 (Vercel)                 카페24
────────────────────              ─────────────────                 ──────
20초마다 「확인해 줘」 ──────────▶ /api/neander/mail (sync)
                                    ├─ POP3 로그인 ─────────────────▶ webmail.<도메인>:995
                                    │  STAT 이 지난번과 같으면 끝
                                    │  다르면 새 것만 RETR → Firestore
                                    ├─ 외부 메일(네이버·Gmail) 2분마다
                                    └─ 보낼 때가 된 예약 메일 발송 (누구의 탭이든)

메일 쓰기 ──────────────────────▶ /api/neander/mail/send
  첨부는 먼저 조각으로 ─────────▶ /api/neander/mail/blob  (768KB 씩, 20MB 까지)
                                    └─ SMTP ────────────────────────▶ smtp.cafe24.com:587
첨부 열기 ──────────────────────▶ /api/neander/mail/attachment
                                    └─ 그때 원문을 다시 RETR ───────▶ (원본 보관소)
백업 zip 올리기 (브라우저가 풀어) ▶ /api/neander/mail/import
받는 사람 메일 프로그램 ─────────▶ /api/neander/mail/t/{id}  (수신확인 · 로그인 없음)
```

- **카페24 는 IMAP 을 열지 않습니다** (143·993 닫힘). POP3(받기)·SMTP(보내기)만
  됩니다. 그래서 ERP 메일함은 카페24 웹메일·휴대폰 메일 앱과 **읽음·폴더가
  맞춰지지 않습니다.** ERP 가 자기 메일함을 따로 갖습니다.
- **POP3 로는 받은메일함만 보입니다.** 카페24 의 보낸메일함·스팸메일함·내 메일함은
  웹메일 → 환경설정 → 메일함 관리 → **백업 zip** 을 받아 「카페24 메일함 가져오기」로
  한 번 가져옵니다. 이후 ERP 에서 보낸 메일은 ERP 보낸메일함에 저절로 쌓입니다.
- **받은 메일은 카페24 서버에 그대로 남깁니다.** 휴지통·스팸메일함에서 「영구 삭제」한
  메일만 카페24 에서도 지웁니다.
- **밀어 주는 쪽이 없습니다.** ERP 를 열어 둔 브라우저가 20초마다(숨은 탭 90초)
  확인을 부릅니다. ERP 를 닫아 두면 확인하지 않고, 다시 열면 곧바로 가져옵니다.

## 1. 기능 — 카페24 사이드바와 맞춘 것

| 카페24 | ERP | 비고 |
| --- | --- | --- |
| 메일쓰기 · 내게쓰기 | 같음 | 내게쓰기는 내 주소로 보내 내게쓴메일함에 남김 |
| 안읽음 · 중요 · 읽음 · 첨부 | 받은메일함 빠른 거르기 | 정렬 키 필드로 거른다 (아래 3) |
| 용량 막대 | POP3 STAT 기준 | 받은메일함만 셈. 전체 용량(기본 1GB)은 설정에서 |
| 받은메일함 | POP3 로 20초마다 | |
| 내게쓴메일함 | ERP 에서 내게쓴 것 | |
| 보낸메일함 · 수신확인 | ERP 에서 보낸 것 + 백업 가져오기 | 수신확인은 1×1 이미지 — 「추정」 |
| 예약메일함 | 예약 발송 | 팀원 누구의 ERP 든 열려 있을 때 나간다 |
| 임시보관함 | 임시저장 (첨부 포함) | |
| 스팸메일함 | 스팸 신고한 보낸 사람 → 자동 | 카페24 서버가 걸러 낸 스팸은 POP3 로 안 보임 |
| 휴지통 | 되돌리기 · 영구 삭제 · 비우기 | |
| 내 메일함 | 폴더 만들기·이름·지우기·옮기기 | |
| 공유메일함 | 내 메일함을 「팀 공유」 | 동료는 읽기 전용 |
| 외부 메일 설정 | 네이버·Gmail·다음 POP3 가져오기 | 2분마다. 보내기는 회사 메일로만 |

서명 관리(메일 설정 → 서명): 계정마다 서명 여러 개(서식·로고 200KB), 「새 메일」·「답장 · 전달」에
자동으로 넣을 서명을 따로 고른다. 쓰기 창이 열릴 때 본문 아래 표시된 칸(`data-nd-signature`)에
들어가고, 창의 「서명」 고르기·보내는 계정 바꾸기로 그 칸만 갈아 끼운다 (`signature.ts`). 저장 자리는
계정 문서가 아니라 `meta/signatures` — 20초마다 읽는 계정 문서를 로고가 불리지 않게. 옛 글자
서명(signature 필드)은 「기본 서명」으로 보이다가 서명을 저장할 때 옮겨진다. 편집기에 들여오는
HTML 은 `sanitizeHtml` 로 on* 속성·script 를 뗀다 (ERP 화면에서 돌지 않게).

쓰기 창: 받는사람(칩 · 주소록 자동완성) · 참조 · 숨은참조 · 제목 · 파일첨부(20MB, 끌어
놓기) · 에디터/HTML/TEXT · 보낸메일함 저장 · 한 사람씩 보내기 · 예약 발송 · 미리보기 ·
임시저장. 주소록은 보낸 주소(최근·자주) + 직접 넣은 주소 + ERP 에 메일을 연결한 동료.

## 2. 켜기

암호화 키 하나가 필요합니다. 카페24 는 비밀번호로만 로그인하므로 ERP 가 비밀번호를
갖고 있어야 하고, Firestore 에는 이 키로 잠근 암호문만 둡니다.

| 환경변수 | 어디에 |
| --- | --- |
| `NEANDER_MAIL_KEY` | `.env.local` + Vercel **neander-erp** 프로젝트 — **같은 값** |

값이 다르면 로컬에서 연결한 계정을 배포 서버가 못 풀어, 각자 설정에서 비밀번호를
다시 넣어야 합니다 (메일은 그대로).

사람마다: 카페24 웹메일에 **그 계정으로**(관리자 아님) 로그인 → 환경설정 → 메일 설정 →
**POP3/SMTP 사용설정** → 사용함. 그 뒤 ERP → 메일 → 연결하기.

⚠️ **서버는 서울(`icn1`)에서 돌아야 합니다** — `vercel.json` 의 `regions`.
2026-09-22 실제로 배포본에서만 보내기가 막혔습니다: 함수가 미국(iad1)에서 도는 바람에
카페24 가 `550 Error: Your Sender IP Address is BLOCKED By User Setting` 으로 끊었습니다
(카페24 계정의 해외 IP 발송 차단). 지역을 서울로 옮겨 풀었습니다. 받기(POP3)는 미국에서도
되던 것으로 보이지만, 같은 이유로 언제든 막힐 수 있습니다.
덤으로 Firestore 가 `asia-northeast3`(서울)라 왕복이 짧아졌습니다.
응답 헤더 `x-vercel-id: icn1::icn1::…` 이면 서울에서 실행 중입니다(가운데가 실행 지역).

## 2-1. 메일을 ERP 안으로 (2026-09-22)

메일 읽기 화면의 **「업무로」** 단추 → 업무요청 · 일일업무 · 회의 자료 중 하나로 옮깁니다.
팀 피드백 「메일 내용을 다른 화면에서도 쓰게 해 달라」로 만들었습니다.

- 제목·본문이 그대로 채워집니다. 업무요청·일일업무는 본문을 400자로 줄이고 주소(링크)는
  뺍니다 — 목록 한 줄에 들어가야 해서입니다. 회의 자료는 본문 전체가 회의록 글이 됩니다.
- **첨부는 회의 자료로 옮길 때만** 따라갑니다. 첨부 원본은 ERP 에 없고 메일 서버에
  있어(위 참조), 서버가 원문을 한 번 받아 회의 첨부(Firestore 조각)로 옮깁니다
  (`app/api/neander/mail/handoff`). 업무요청·일일업무에는 첨부 자리가 없습니다.
- 만들어진 문서에는 `mail` 참조(`MailRef`)가 남아 **「메일에서 옴」 칩**으로 보이고,
  누르면 그 메일이 열립니다 (`/neander/mail?acct=…&box=…&id=…`). 칩에는 제목·보낸 사람이
  함께 적혀 있어, 그 메일함에 못 들어가는 사람도 무엇에서 왔는지는 읽을 수 있습니다.
- 보낸 사람 이름이 없는 알림 메일이 흔해서 참조는 `mailRefOf()` 로만 만듭니다 —
  Firestore 는 undefined 를 거부합니다.

## 3. 저장 자리

```
neander_mail_accounts/{계정 키}             계정 · 주인(user) · 암호문 · 폴더 · 차단 목록 · 외부 메일
  ├─ meta/uidls · meta/uidls_<외부id>       카페24(외부)에서 이미 본 메일 (UIDL 해시)
  ├─ meta/contacts                          주소록
  ├─ inbox · self · sent · drafts · spam · trash/{id}
  └─ f_xxxxxxxx/{id}                        내 메일함
neander_mail_scheduled/{id}                 예약 메일 (모두 한 곳 — 누구의 확인이든 찾게)
neander_mail_blobs/{id}/parts/{n}           첨부 조각 (Storage 버킷이 없어서)
neander_mail_track/{trackId}                수신확인
```

- 서버(Admin SDK)만 읽고 씁니다. 대상은 **로그인한 사람 자신의 메일함**이고, 예외는
  동료가 「팀 공유」한 폴더를 읽기 전용으로 여는 것뿐입니다 (`resolveBox`).
- **복합 색인을 쓰지 않습니다** (게시에 사용자 로그인이 필요). 메일함은 하위 컬렉션,
  거르기는 **정렬 키 필드**: 안 읽은 메일에만 `byUnread`(=date) 를 두면
  `orderBy("byUnread")` 가 그 필드가 있는 것만 날짜순으로 준다. `byRead · byStar ·
  byAttach` 도 같다. 상태가 바뀌면 키를 붙이고 뗀다 (`readPatch` · `starPatch`).
  옛 문서는 첫 확인 때 한 번 붙인다 (`schema: 2`).
- **Firebase Storage 버킷이 없습니다.** 원문·받은 첨부는 카페24 서버가 원본 보관소 —
  누를 때 다시 받습니다. 보낼 첨부·임시저장·예약 첨부는 Firestore 조각(768KB)에 둡니다.
  아무도 잡지 않은 조각은 하루 뒤 지웁니다.
- 백업에서 가져온 메일은 원문이 없어 **첨부를 열 수 없습니다** (이름만). 같은 백업을
  다시 올려도 Message-ID 로 겹침을 거릅니다.

## 4. 한도·함정

| 무엇 | 한도 | 이유 |
| --- | --- | --- |
| 새 메일이 뜨기까지 | ERP 가 열려 있으면 ~20초 | POP3 에 푸시가 없다 · LOGIN-DELAY 10초 |
| 보내는 첨부 | 합쳐서 20MB | 카페24 SMTP 30MB(base64 후) · 조각으로 올려 요청 4.5MB 를 비킨다 |
| 본문 속 이미지 | 한 장 1.5MB | 보내기 요청 4.5MB 안 · 보낼 때 cid 첨부로 바뀐다 |
| 받는 첨부 | 제한 없음(메일 크기) | 4MB 넘으면 조각으로 나눠 내려준다 |
| 예약 발송 | 팀원 누군가 ERP 를 열어 둔 때 | 상주 서버가 없다 |
| 외부 메일 | 2분마다 | 남의 서버를 20초마다 두드리면 막힌다 |

- ⚠️ **카페24 POP3·SMTP 는 TLS 1.0 만 받습니다.** `cafe24.ts` 의 `LEGACY_TLS` 로 허용.
  Node 20·22 확인. POP3 인증서는 `*.cafe24.com` 이라 이름만 카페24 이름으로 확인.
- **확인 오류는 2분 넘게 이어질 때만 알립니다.** 계정 문서의 `errorSince`(처음 실패한 시각)를
  보고 메일 화면 위 알림을 띄운다 (`MailProvider` `ERROR_GRACE_MS`). 네이버·Gmail 은 1분에 한 번만
  실제로 붙고 그 사이 20초 확인은 건너뛰는데, 건너뛴 확인도 지난 실제 확인의 오류를 그대로 돌려준다 —
  예전에는 「ok」로 돌려줘 알림이 1분마다 떴다 사라졌다 했다 (2026-09-18).
- ⚠️ **비밀번호가 두 번 연속 틀리면 멈춥니다** — 20초마다 틀린 로그인이 쌓이면 카페24 가
  계정을 잠급니다. 설정에서 비밀번호를 다시 넣을 때까지 확인하지 않습니다.
- **보낸 메일은 카페24 웹메일 보낸메일함에 남지 않습니다.** 「사본 남기기」(기본 켬)면
  내 주소를 봉투에만 넣어 받은편지함에 사본이 남고, ERP 는 그 사본을 보낸 메일에 이어
  보낸 첨부를 다시 열 수 있게 합니다. 한 사람씩 보내기는 사본을 한 통만 남깁니다.
- **수신확인은 추정**입니다. 이미지를 막으면 열어도 미열람, 애플 메일·Gmail 은 미리
  불러와 안 열어도 열람으로 뜰 수 있습니다. 보낸 직후 5초는 세지 않습니다.
- 받은 HTML 본문은 `sandbox`(스크립트 없음) iframe + CSP 로 격리해 그립니다.
